# Отчёт о проделанной работе за неделю (26.10–01.11.2026)

## Тема проекта

**«Технологический трекер Hacker News»** — веб-сервис аналитики и прогнозирования популярности технологий на основе постов и комментариев Hacker News.

## Кратко

На этой неделе перешли от реализации анализа тональности к проверке его качества. Подготовлена пилотная разметка 300 комментариев, сравнены шесть режимов оценки общего и аспектного тона. Порог теперь подбирается на отдельной части данных, а итоговая метрика считается на отложенных обсуждениях. По тем же статьям впервые получены численные оценки precision/recall словаря технологий. Начат анализ вовлечённости: на полной базе статей построены регрессионные модели числа комментариев. Главный результат недели — появились измерения, по которым можно обсуждать ограничения методов, а не только отдельные удачные примеры.

## Проделанная работа

### 1. Данные и пилотная разметка комментариев
- Для экспериментов использована база с **93 713 статьями и 1 045 657 комментариями**. Это исторические данные за апрель–август 2024 года. Работа велась на отдельной копии БД.
- Выгружено 300 разных комментариев: по 50 для Linux, GPT, Python, Rust, JavaScript и Windows. Выборка охватывает 189 статей. Для каждой технологии примерно половина комментариев содержит явное упоминание по паттернам, половина — нет. Сид фиксирован, поэтому выборку можно воспроизвести.
- В CSV добавлены `story_id` и заголовок статьи. Они нужны и для разбора смысла реплик, и для разделения данных по обсуждениям.
- Комментарии размечены по двум полям, запланированным на прошлой неделе:
  - `label_comment` — общий тон собственной прозы автора: −1, 0 или 1;
  - `label_tech` — отношение к технологии: −1, 0 или 1; пусто, если отношения к ней в тексте нет.
- **Разметка выполнена с помощью ИИ, а не человеком.** Её происхождение явно записано в `annotation_source`; для неоднозначных примеров добавлены пояснения. Это предварительный набор для экспериментов, который ещё предстоит независимо проверить вручную.
- По общему тону получено 98 отрицательных, 127 нейтральных и 75 положительных меток. Отношение к технологии удалось разметить в 177 комментариях: 53 отрицательных, 81 нейтральный и 43 положительных. Остальные 123 реплики обсуждают другую тему или не позволяют определить отношение к технологии.

### 2. Разделение данных и выбор порога
- Скрипт `analytics.embeddings.scripts.evaluate_sentiment` дополнен оценкой на отложенных данных. Раньше лучший порог выбирался на той же выборке, на которой считался F1, поэтому результат был оптимистичным.
- Данные разделяются **по статьям**, а не по строкам. Комментарии одной ветки не могут одновременно попасть в подбор порога и итоговую проверку:

| Часть | Статей | Комментариев | Назначение |
|---|---:|---:|---|
| Train | 95 | 154 | Обучающая часть |
| Validation | 47 | 59 | Выбор метода и порога |
| Test | 47 | 87 | Итоговая оценка |

- Пороги перебираются по сетке от 0.05 до 0.50. Для каждого режима выбирается лучший порог по macro-F1 на validation, после чего он фиксируется для test. Сам режим тоже выбирается по validation, без просмотра тестовых меток.
- Для Word2Vec и bootstrap отдельно выгружено 3000 строк из других обсуждений: 2986 уникальных комментариев к 730 статьям. Все 189 статей оценочной выборки исключены из этой выгрузки до обучения.
- В `vader_aspect` исправлена подстановка общего тона вместо отсутствующей аспектной оценки. Если предложения с упоминанием технологии нет, метод теперь отказывается от оценки. На размеченном примере такой отказ учитывается как ошибка; отдельно выводится доля комментариев, для которых предсказание вообще получено.

### 3. Сравнение методов тональности
Сравнены три варианта VADER, собственный лексикон с расширением через Word2Vec, его аспектный вариант и bootstrap-классификатор. Для каждого из двух видов разметки порог подбирался отдельно.

| Режим | Test macro-F1: общий тон | Test macro-F1: отношение к технологии |
|---|---:|---:|
| `vader` | 0.491 | 0.419 |
| `vader_aspect` | 0.332 | 0.518 |
| `vader_window` | 0.489 | 0.502 |
| `lexicon` | 0.377 | 0.380 |
| `lexicon_aspect` | 0.415 | 0.361 |
| `bootstrap` | 0.285 | 0.234 |

- **Общий тон.** По validation выбран VADER с порогом **0.30**: macro-F1 = 0.506 на validation и 0.491 на test. Более сложные методы на этой выборке преимущества не дали.
- **Отношение к технологии.** По validation среди всех режимов выбран VADER с порогом 0.50, но его тестовый F1 составил только 0.419. Аспектный VADER на test оказался лучше, однако выбирать его задним числом по тестовой метрике нельзя. Выбор метода для этой задачи пока неустойчив.
- Аспектный VADER смог дать оценку для 84.8% тестовых комментариев с заполненной технологической меткой. Для остальных отношение к технологии было определено при разметке, но явного упоминания по паттернам не нашлось.
- Для лексиконных методов и bootstrap обучены небольшие модели Word2Vec: skip-gram, размерность 50, окно 5, `min_count=2`, 30 эпох. Модель контекста проходит проверку на вырожденность: средняя близость технологий 0.363. Модель по 730 коротким заголовкам вырождена — близость 0.950. Это ограничивает интерпретацию результата bootstrap: сравнивался предварительный вариант, а не окончательно подобранная модель на полном корпусе.
- Настройки рабочего предрасчёта автоматически не заменялись. Один общий порог для общего и аспектного тона эти результаты не подтверждают.

### 4. Precision/recall словаря технологий
- Добавлен скрипт `db.scripts.export_tech_sample`: он выгружает заголовки тех же статей, по которым оценивалась тональность, и дополнительную случайную выборку. В эксперимент вошли **189 статей из обсуждений и 100 случайных статей** вне этого набора.
- Каждый заголовок проверялся целиком, по всем технологиям фиксированного каталога из 121 ключа. Для заголовка без технологий явно записывается пустой список `[]`; незаполненное поле не считается отрицательным примером.
- Разметка заголовков также выполнена ИИ с явной отметкой происхождения. Однозначные названия инструментов экосистемы учитываются: например, Mypy относится к Python, Flutter — к Dart. Упоминания технологий вне каталога отмечаются отдельно и не включаются в recall по этому каталогу.
- Скрипт `analytics.embeddings.scripts.evaluate_tech` считает micro precision/recall/F1, метрики по отдельным технологиям и список ошибок.

| Выборка | Статей | Precision | Recall | F1 |
|---|---:|---:|---:|---:|
| Статьи из оценки тональности | 189 | 0.986 | 0.946 | 0.966 |
| Случайные статьи | 100 | 0.933 | 0.824 | 0.875 |
| Вместе | 289 | 0.982 | 0.937 | 0.959 |

- В объединённой выборке получилось 224 верных упоминания, 4 ложных срабатывания и 15 пропусков. Среди ошибок — пропуски коротких названий Go/C/R, BSD, Mypy и Swift; ложные срабатывания на художественном `poetry`, общем слове `bundler` и графических «окнах».
- Разница между двумя выборками существенна: статьи для тональности уже отобраны по словарю и частым технологиям, поэтому их результат выглядит лучше. В случайной части всего 17 эталонных упоминаний, и её recall пока нельзя считать устойчивой оценкой для всего HN.

### 5. Первые результаты анализа вовлечённости
- Начат следующий этап: оценка того, как наличие технологии в заголовке связано с ожидаемым числом комментариев. Используются модели для счётных данных — **Poisson** с робастными ошибками и **отрицательная биномиальная NB2**. Коэффициенты переводятся в IRR: множитель ожидаемого числа комментариев.
- В расчёт вошли все 93 713 статей, включая 84 293 без обнаруженных технологий. Они нужны как база сравнения; использование только статей о технологиях исказило бы постановку задачи.
- Начальная модель включает индикаторы технологий и контроли формата: число слов в заголовке, `Show HN`, `Ask HN`, наличие ссылки. Взаимодействия технологий и признаки Word2Vec пока отключены, чтобы сначала проверить базовые оценки.
- Среднее число комментариев — 10.29, дисперсия — 2282.09, то есть примерно в 222 раза больше среднего. Это сильная сверхдисперсия, поэтому NB2 выглядит более подходящей исходной моделью, чем обычное пуассоновское предположение. Оценка параметра NB2 `alpha` составила 20.55; обе модели сошлись.
- Пример результата NB2: для Windows IRR = **2.14**, 95% интервал **[1.49; 3.06]**. Для Rust IRR = 0.99 с интервалом [0.70; 1.39], то есть отличия от единицы на этих данных не видно.
- Это пока наблюдаемые связи, а не причинный эффект добавления названия технологии в заголовок. Время публикации, тематика и видимость статьи ещё не контролируются. Число комментариев берётся из метаданных HN, а не подсчитывается по скачанным ответам.

### 6. Воспроизводимость и тесты
- В выборках сохраняются идентификаторы статей и комментариев; сиды разделения и параметры моделей фиксированы. Для обучения Word2Vec используется один поток и детерминированная инициализация.
- Добавлены проверки отсутствия пересечения обучающих и оценочных статей, выбора метода без тестовых меток, обработки отказов аспектного режима, подсчёта precision/recall и расчёта IRR без эмбеддингов.
- Bootstrap корректно пропускается, если уверенных псевдометок недостаточно или в них представлен только один класс.
- Полный набор Python-тестов: **348 passed**. Проверка стиля Ruff проходит.

## Проблемы и риски
- Полученные метрики основаны на AI-разметке. Независимая ручная проверка человеком ещё не выполнена; числа показывают согласие с предварительным рецензентом, а не окончательное качество на эталоне.
- Для оценки отношения к технологии на test осталось только 46 размеченных комментариев. Разница между методами может заметно меняться при другом разделении статей.
- Выборка тональности ограничена шестью частыми технологиями и специально сбалансирована по упоминаниям. Переносить её результаты на все обсуждения HN без дополнительной проверки нельзя.
- Высокая объединённая точность словаря частично связана с отбором статей через этот же словарь. Нужна более крупная независимая случайная выборка.
- Модель Word2Vec заголовков для пилотного bootstrap вырождена. Её нужно переобучить на большем объёме, прежде чем делать вывод о пределе качества этого подхода.
- IRR пока не проверен на устойчивость по времени и редким технологиям. Интервалы NB2 условны на оценке `alpha`; поправка на множество одновременно проверяемых технологий не применялась.

## Планы на следующую неделю
- Продолжить анализ вовлечённости: проверить устойчивость IRR на разных временных отрезках, влияние редких технологий и контроля формата статьи.
- Проверить часть AI-разметки вручную, разобрать расхождения общего и аспектного тона; расширить выборку, если выбор метода останется неустойчивым.
- Подготовить отдельную контрольную выборку для словаря технологий и уточнить неоднозначные паттерны, не подбирая правила по итоговому тесту.
- Подготовить сохранение результатов анализа вовлечённости в предрасчёт и критерии, по которым ненадёжные оценки не будут показываться как уверенные выводы.
